## Columns

- **Last reproduced on** — the version the behaviour was *actually observed on*. A migrated row
  that has not been re-run says so and names the version it was **found** on instead. That
  distinction is the whole point of the column: an unverified age is how a fixed bug stays on a
  list for months. Never promote a found-version to a reproduced-version without re-running it.
- **Filed** — the upstream issue or PR, or `no`. 40 rows carry one.
- **Suggested fix** — a short inline fix, or a `→ FIX-NN` pointer into [`suggested-fixes.md`](suggested-fixes.md).
- **How to reproduce** — the command or the sequence. Where a row named a sentinel test, that test
  *is* the reproduction (54 of 83 rows).
  Rows reading *not recorded* need one written the next time anyone touches them.

- **Reproduce before you write it.** How-to-reproduce is the command or the sequence, not prose. A
  row nobody can reproduce is a rumour.
- **Version-stamp what you actually observed**, and say which part is fresh. If only the source was
  re-read, the row is `pending-retest`, not `open`.
- **Record, never fix.** The framework is read-only in this repo —
  `documentation-testing/readme.md` rules 10 to 12.
- **Never document a fault on a page.** Defects are fixed in the framework; documentation states
  intended behaviour. That rule is why several of these rows exist instead of paragraphs on
  tina4.com.
- **A `PY-NN-NN` row still needs a chapter trace.** Rules 11 and 12 are unchanged by the move: that
  ID form is earned only by a quoted documented claim tested inside `documentation-testing/`. Rows
