# 2026-08-11 — Python: Tina4 vs Flask, FastAPI, Django

First feature-matched run. Supersedes the scratch measurement of 2026-08-07 that compared a
three-route app with no database, no auth and no OpenAPI, and found no line saving at all.

**Machine:** Fedora Linux 7.1.6 (x86_64), CPython 3.14.5, `uv` 0.11.14.
**Spec:** [`spec/bookmarks-app.md`](../spec/bookmarks-app.md) — R1 schema, R2 public list from
the database, R3 JWT-protected write with validation, R4 login issuing a token, R5 HTML page
through an inheriting template, R6 generated OpenAPI docs.

## Verification

Every app passed all seven acceptance checks of `scripts/verify-app.sh` before it was
counted. None was counted on a first attempt without being run.

| Framework | Port | OpenAPI path | Result |
|---|---|---|---|
| Tina4 | 7501 | `/swagger/openapi.json` | 7/7 first run |
| Flask | 7502 | `/openapi.json` | 7/7 after adding `OPENAPI_URL_PREFIX` (see below) |
| FastAPI | 7503 | `/openapi.json` | 7/7 first run |
| Django | 7504 | `/openapi.json` | 7/7 on the second attempt (see below) |

Two apps failed before they passed, and both failures are findings rather than mistakes:

- **Flask** generated its OpenAPI document but did not serve it. `/openapi.json` returned
  404 until `OPENAPI_URL_PREFIX`, `OPENAPI_SWAGGER_UI_PATH` and `OPENAPI_SWAGGER_UI_URL`
  were set — three config lines with no default.
- **Django** returned **405** on `POST /api/bookmarks`. Django resolves URL paths exactly,
  so GET and POST on one path cannot be two functions with two permission sets. The two
  views were merged into one that branches on `request.method` and checks
  `request.user.is_authenticated` itself.

### What each framework had to add

The list is the argument, not a footnote.

- **Tina4** — nothing. One package, and every requirement met by what ships.
- **Flask** — `flask-sqlalchemy`, `pyjwt`, `flask-smorest`. Three direct, 13 more transitively.
- **FastAPI** — `uvicorn`, `sqlalchemy`, `jinja2`, `pyjwt`. Four direct, 13 more transitively.
- **Django** — `djangorestframework`, `drf-spectacular`, `djangorestframework-simplejwt`. Three direct, 12 more transitively.

Django installs **2** third-party distributions on its own, not the 20 the site's current
comparison table claims. It reaches 16 only because of what the spec requires it to add.

### Where the difference comes from

Tina4 wrote no authentication code and no OpenAPI code:

- Non-GET routes are closed by default, and the default guard accepts the JWT that
  `Auth.get_token` issues. The only auth code in the Tina4 app is the login route itself.
- The OpenAPI document is generated from the declared routes with no annotations and no
  configuration.

Flask and FastAPI each hand-rolled the same two things: a token-checking wrapper with
`jwt.decode` in a `try/except`, and a token-issuing view with payload and expiry
arithmetic. Django avoided hand-rolling by adding two more packages.

## What Tina4 lost on

Recorded with the same prominence as the wins; readme rule 9.

- **The generated OpenAPI is shallow.** Tina4's spec documents the path and method but
  carries **no `requestBody` schema** and only a generic `200` response. Flask and FastAPI
  document the request body and real response codes (`201`, `422`), because their OpenAPI
  layers make schema declaration mandatory — which is also part of why they cost more
  lines. Tina4's docs are free partly because they ask for less. Whether Tina4's
  `@description` and swagger decorators close that gap was not explored; this is
  out-of-the-box behaviour only.
  Django's is equally shallow here — `drf-spectacular` cannot infer a serializer from an
  `@api_view` function, so it also produced no `requestBody`. Its three packages bought no
  more depth than Tina4's zero.
- **No request typing or validation.** `request.body` is an untyped dict. FastAPI's pydantic
  models validate and coerce before the handler runs; Tina4's `if not data.get("url")` is a
  hand-written check. For anything larger than this app, that difference grows.
- **Twice the files.** Six against Flask's and FastAPI's three. Tina4's conventions spread
  code across `migrations/`, `src/orm/`, `src/routes/` and `src/templates/`, which is a real
  cost in a small app even if it pays off in a large one.
- **Django's larger install buys things this spec never asked for** — the admin site, the
  full auth system with permissions and groups, DRF's browsable API, and 19 applied
  migrations of infrastructure. Comparing install sizes without saying so is dishonest.
- **Ecosystem.** Not measurable here, and not close. Nothing in this table speaks to how
  many people have already hit your bug.

## Capability gaps

None. All four frameworks met all six requirements. No framework needed a workaround the
spec forbids.

## Judgement calls

Every call that could have gone either way, and which way it went. Where a call favoured a
comparative, that is deliberate — readme rule 4.

| Call | Resolved | Effect |
|---|---|---|
| Tina4 schema: migration file vs `ORM.create_table()` | Migration file | Costs Tina4 one file and 7 lines. Matches what Django and Alembic do. |
| Tina4 login: own route file vs folded into `bookmarks.py` | Own file | Costs Tina4 one more file. |
| Flask OpenAPI: `flask-smorest` vs `apiflask` | smorest | `apiflask` is terser in code but measured **26** distributions and 26.2 MB — 9 more packages. Chose the leaner install for Flask. |
| Flask database: `flask-sqlalchemy` vs stdlib `sqlite3` | flask-sqlalchemy | Idiomatic. `sqlite3` would drop three packages at the cost of hand-written SQL; not built. |
| FastAPI schema: `create_all()` vs Alembic | `create_all()` | Saves FastAPI two packages and a migrations directory. R1 permits it. |
| Django views: `@api_view` functions vs `APIView`/`ViewSet` | Functions | Fewest lines for Django. |
| Django JWT: `simplejwt` vs hand-rolled PyJWT | simplejwt | Fewer lines for Django, at the cost of one package. |
| Generated migrations counted? | No | Django's `0001_initial.py` and Tina4's `app.py` are both scaffolder output, both uncounted. |

## Loose ends

- **Django's spec is YAML by default.** `drf-spectacular` serves
  `application/vnd.oai.openapi` at `/openapi.json`; JSON needs `?format=json`. R6 is met,
  but the default content type is not JSON despite the path.
- **Throughput was not measured.** Needs matched hardware and a load generator; `hey` is not
  installed here. Separate exercise, separate spec.
- **The Flask `apiflask` variant has no line count** — only its package figures were
  measured. If the line difference matters to the argument, build it.
- **One language only.** PHP, Ruby and Node.js follow the same spec with their own
  comparatives.
